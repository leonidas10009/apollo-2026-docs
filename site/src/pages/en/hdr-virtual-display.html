HDR game streaming and the virtual display

Apollo 2026 can create a virtual monitor on demand with the resolution, refresh rate and HDR state requested by the client. This guide covers the Windows setup, what to check when HDR looks wrong, and the limits of the current implementation.

How the virtual display works

Apollo uses SudoVDA, a virtual display adapter bundled with the Windows installer. When a stream starts, Apollo creates a display that matches the client configuration. When the session ends, the display is removed.

Each paired client gets a fixed display identity. Windows remembers the resolution, position and HDR settings for that identity, so the same tablet or TV keeps its layout between sessions without scripts or manual switching.

Remove other virtual display solutions first. Dummy plugs, vendor IDD drivers and leftover virtual monitors can conflict with SudoVDA and produce black screens or duplicated displays. Disable them in Device Manager and in the Apollo configuration before troubleshooting anything else.

Setup

  1. Enable HDR on the host

    Open Settings → System → Display → HDR and turn HDR on. If the PC has no HDR-capable monitor attached, Windows may hide the option; an EDID emulator or the virtual display itself can provide an HDR-capable target.

  2. Confirm SudoVDA is installed

    In Device Manager, look for SudoMaker Virtual Display Adapter under Display adapters. If it is missing, rerun the Apollo installer and keep the virtual display component selected.

  3. Configure the virtual display in Apollo

    In the Web UI, open Configuration → Audio/Video and check the virtual display options. The important ones are:

    • Virtual display: creates the display when a stream starts.
    • HDR option: set to auto to follow the client request when the display supports it.
    • Fallback mode: resolution used when the client does not request one, in WidthxHeightxFPS format.
    • Isolated virtual display: moves the virtual display so it does not overlap a physical monitor.

  4. Enable HDR on the client

    In Moonlight or Artemis 2026, open the stream settings and enable HDR. If the client option is off, the host sends SDR and an HDR desktop can look overexposed.

  5. Calibrate

    Stream the Windows HDR Calibration app to the client and save a profile for streaming. In-game brightness and HDR calibration may still need adjustment because the client panel is usually dimmer than a desktop monitor.

When HDR looks wrong

Washed out or grey image

The stream is probably SDR while the host desktop is in HDR. Check the client HDR toggle first, then the Apollo HDR option.

Wrong colors only on the virtual display

Some virtual display configurations report an incorrect HDR state. Apollo includes an optional workaround that turns HDR off and on again at stream start. Set dd_wa_hdr_toggle_delay = 500 in the configuration and test. Leave it at 0 unless you actually have the problem: it adds delay to every stream start.

HDR option is missing

The GPU encoder may not support HEVC Main 10 or AV1 10-bit. Check the encoder list in the Web UI, update the GPU driver, and try HEVC instead of AV1 (or the reverse).

Stream starts on the wrong monitor

Enable Isolated virtual display or set the display position explicitly. Windows may also remember a layout from a previous client identity; remove the paired client and pair it again to reset the layout.

Linux and macOS

The SudoVDA virtual display is Windows-only. HDR streaming is officially supported on Windows hosts and experimental on Linux, where it requires the KMS capture backend and a compositor with HDR support, such as Gamescope or KDE Plasma 6. X11 and NvFBC capture do not support HDR.

On Linux, virtual outputs are provided by the compositor (for example a wlroots output in Hyprland) rather than by Apollo itself.

Dual-GPU laptops: if the virtual display is created on the integrated GPU, the stream may be captured from the wrong adapter. The project README documents the recommended configuration for hybrid graphics.
